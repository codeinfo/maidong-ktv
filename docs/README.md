# 文档管理规则（docs）

> 状态：现行 ｜ 更新于 2026-11-15 ｜ 适用范围：`E:\ktv` 仓库内全部非代码文档
> 本文件既是规则，也是索引；新增/移动/废弃文档时必须同步更新第 6、7 节。

---

## 1. 目录职责

```
docs/
├─ README.md                     本规则 + 索引
├─ analysis/                     对比分析、差异清单、决策记录（"为什么这么选"）
├─ reports/                      测试报告与验收记录（"实测结果"）
├─ features/                     功能说明、模块设计、迁移说明（"这块怎么实现的"）
├─ plans/                        优化清单、迭代排期、TODO（"接下来做什么"）
├─ assets/
│   ├─ screenshots/
│   │   ├─ 真机测试/              NX507J 真机截图证据
│   │   └─ 设备验证截图/          i歌霸版本验收截图
│   └─ test-data/                测试素材（音频、JSON 断言等）
└─ archive/                      已被取代/废弃的文档（保留 30 天后可删）
```

**判断归属的一句话**：写「结论与依据」进 `analysis/`，写「实测到的东西」进 `reports/`，写「功能怎么用/怎么实现」进 `features/`，写「还没做的事」进 `plans/`。

## 2. 命名规则

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 新文档（推荐） | `YYYY-MM-DD-主题.md` | `2026-11-20-遥控器焦点链路排查.md` |
| 长期专题文档 | `主题.md`，必须在索引登记 | `安卓4.4-功能优化清单.md` |
| 截图 | `NN-场景.png`，同一张图只留 png | `30-TS播放.png` |
| 测试素材 | `用途-参数.扩展名` | `测试歌曲-44k单声道.wav` |

禁止：`新建文档`、`最终版`、`最终版2`、`副本`、`1.md`、`2.md`、纯日期文件名。
存量 8 份文档保留原名（改名会破坏既有引用），以索引表为准。

## 3. 状态与生命周期

**新建文档必须在文首写一行状态**：

```
> 状态：现行 ｜ 更新于 YYYY-MM-DD ｜ 负责人：XXX
```

| 状态 | 含义 | 处置 |
| --- | --- | --- |
| 现行 | 与当前代码/设备结论一致 | 正常维护 |
| 历史 | 结论被取代，但仍有留证价值（如设备/工具已不存在） | 留在原目录，文首标注取代它的新文档 |
| 废弃 | 无参考价值 | 移入 `archive/` |

**同一主题产生新文档时**：旧文档状态改为「历史」，并在文首加一行 `> 已被 <新文档路径> 取代`。

---

## 4. 归档与清理

- **触发归档**：① 被新版本取代；② 结论已过时（设备、工具链、依赖已不存在）；③ 一次性过程稿。
- **归档动作**：移入 `archive/`，文件名不变，文首补 `> 状态：废弃 ｜ 归档于 YYYY-MM-DD ｜ 原因：…`。
- **允许删除**：`archive/` 内满 30 天，且全仓库 `grep` 无任何引用。
- **大文件**：单文件 > 50 MB 一律不进 `docs/`（放仓库外或 `docs/assets/test-data/` 并加入 `.gitignore`）。

---

## 5. 引用规则

1. 文档间引用用**相对路径**：`../features/音源更新说明-i歌霸.md`，不用绝对路径，也不用《书名号》。
2. 截图引用相对 `../assets/screenshots/<分组>/NN-场景.png`。
3. **移动或删除文件后必须同步修引用**：`grep` 旧文件名确认零残留后再提交。

---

## 6. 版本管理

- `docs/` 全部纳入 git，提交信息前缀 `docs:`（例：`docs: 整理文档目录并建立管理规则`）。
- 二进制仅当单文件 ≤ 50 MB 时入库。
- 代码仓库只放文档与必要证据图，不放整库数据、APK、日志。
- **主分支约定（2026-11-15 起）**：`master` 为 Android 4.4 线主分支；`android-4.4.4` 保留为同一提交的发布线别名（仍跟踪 `origin/android-4.4.4`）。两者指向同一 HEAD，不要各自提交造成分叉。
- 上游参照线只在 `gitee-master` / `gitee-igeba-media`（跟踪 Gitee，与主分支为**无关历史**，禁止直接 merge）。
