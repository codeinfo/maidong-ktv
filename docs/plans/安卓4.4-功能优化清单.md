## 二、P0 　影响现场可用 / 阻塞发版（先做这 5 项）

| 编号 | 优化项 | 现状证据 | 4.4 可行性 | 主要改动点 | 预估 |
| --- | --- | --- | --- | --- | --- |
| P0-1 | **补齐正式签名，恢复 release 构建** | `app/build.gradle` 写死 `file("../../ktv_keystore.jks")`；两个候选路径实测都不存在 | ✅ 与 API 无关 | 放回原 keystore → 与已装 1.1.0 同签名才能覆盖升级；拿不到就只能换新签名并卸载重装 | 0.5 天（拿到原 keystore 后） |
| P0-2 | **平台兜底路径补齐「双音轨」原唱/伴唱切换** | 实测 `KtvVideoView.kt:276`：`selectAudioTrack` 只在有 `ijkPlayer` 时用 `selectTrack` 切；无 IJK 时**恒返回 false**。注：声道级切换**已经可用**（`selectAudioChannel` 平台分支用 `setVolume(L,R)` 做左右增益），缺的是「同一文件内两条独立 audio track」这类片源 | ⚠️ 需替代实现：平台 MediaPlayer 只能出 track 0，无法换轨。可选替代：① 检测 track 数，无 IJK 时把双音轨片源自动降级为声道模式并提示；② 用双 MediaPlayer 实例同步播放同一文件并各自 `selectTrack`（4.4 上易音频不同步，风险高） | `KtvVideoView` 平台分支加 track 数探测与降级提示；`MainActivity` 切唱按钮按结果给反馈 | 1 天 |
| P0-3 | **内嵌字幕（MKV/TS）支持** | 全仓库只有「片头字幕」开关与 LRC 文本歌词，无字幕轨渲渲染（`subtitle` 仅出现在 `Song.subtitleUrl` 字段映射） | ✅ IJK 支持 `subtitle` 相关 option；仅 ARM 真机生效，平台兜底不支持 | `KtvVideoView` IJK 初始化时开 `subtitle` / `subtitle-bg` 选项，配一个开关 | 1 天 |
| P0-4 | **真机屏幕适配（800×1280 / density 160）闭环** | 真机 `wm size` 实测 Override 800×1280、density 160，而 UI 按 1280×720 调；历史上已出现「榜单九宫格撞字」「面包屑压 Tab」两类裁切 | ✅ 纯布局 | 抽取尺寸基线（`TvUiScale` 思路：按 `screenWidthDp` 算缩放系数），替换写死的 dp | 2 天 |
| P0-5 | **遥控器行内 ←/→ 事件链路修复** | `KeyTrace` 实测：↑/↓ 已按行移动，但 ←/→ 连 KeyTrace 都没打印，说明事件在 Activity 之前被吞 | ✅ 纯事件分发 | `MainActivity.dispatchKeyEvent` / 列表控件父级拦截点定位；`TvListView` 命中即处理、未命中 `super` | 1.5 天 |

## 六、结构性风险（会影响上面每一项的落地成本）

1. **`MainActivity.kt` 已达 399 KB**（全仓库最大的单文件，`MuseDatabase` 只有 22 KB），TV 焦点、布局、播放控制、设置页全在里面。P0-4/P0-5 这类改动每次都要全量回归，建议**先按「播放控制 / TV 焦点 / 设置页」拆三个文件**再做功能（+2 天，但后续每次改动省 0.5～1 天）。
2. **4.4 的 WebView 是 Chromium 33**：任何 H5 侧（手机点歌页）都不能用 ES6 语法与 `fetch`/`Promise.then` 之外的现代 API，需按 ES5 写或加 polyfill。
3. **验证环境只剩真机**：SDK 里已无 emulator 目录，`ktv_api19` AVD 不可用；真机 `wm` 覆写为 800×1280/density 160，且该 ROM 上 `input tap` 在应用内不生效，只能靠 `keyevent` + `KeyTrace` + 截图。

## 八、每项的验证方式（4.4 真机口径）

```powershell
# 构建（现有报告验证过的参数，Kotlin 守护进程需 in-process）

.\gradlew.bat assembleDebug --no-daemon --console=plain "-Dkotlin.compiler.execution.strategy=in-process"

# 装机与启动
& "E:\Android\Sdk\platform-tools\adb.exe" -s NX507J install -r app\build\outputs\apk\debug\app-debug.apk
& "E:\Android\Sdk\platform-tools\adb.exe" -s NX507J shell am start -n "com.local.ktv.qa/com.local.ktv.MainActivity"

# 关键证据：焦点与播放日志（KeyTrace 已落盘）
& "E:\Android\Sdk\platform-tools\adb.exe" -s NX507J shell "cat /sdcard/MaidongKTV/logs/app.log | tail -40"
```

- **P0-2**：分别在「有 IJK 的 ARM 真机 / 无 IJK 环境」播一首双音轨片源，切「原唱/伴唱」：IJK 路径应换轨生效；无 IJK 路径应给出降级提示而不是静默失效。声道模式（`accomp` 1/2）用 `setVolume` 增益，可用 `dumpsys media.audio_flinger` 观察左右声道电平。
- **P0-4**：`wm size` 覆写下逐页截图，检查榜单九宫格、面包屑/Tab、全屏播放条三处（历史上都出过裁切）。
- **P0-5**：按键序列 `↓ ↓ → ←`，`KeyTrace` 必须打印出 `key=22/21` 且焦点在同一行内移动。
