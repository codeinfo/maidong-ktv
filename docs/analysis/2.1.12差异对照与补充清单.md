## 二、已对齐 / 已补充

### 2.1 音源（i歌霸）
新增 `IgebaApiClient` / `IgebaSessionVault` / `IgebaAccount` / `IgebaAccountDialog` / `SongSourceRouter`，改造 `Song` / `SongOkDownloadManager` / `MainActivity` / `KtvApplication`。详见 `../features/音源更新说明-i歌霸.md`。

实测结论（不是推断）：
- `cloud.php`（目录接口）对所有 `VER`、所有 UA 都返回 `请使用鸿蒙客户端.` → 线上同步走不通，只能内置快照。
- `telnet.php` 的 `GET_SONGADDR` 可用，响应含 `FileUrl / VoiceChannel / Rights`，地址是 http（4.4 无 TLS 问题）。
- `VoiceChannel` 即原伴唱声道模式（0=不切、1=左伴右原、2=左原右伴），已写回 `Song.accomp`，与原声道切换逻辑一致。

### 2.2 曲库（i歌霸目录）
- 新增 `IgebaCatalog.kt`：与 `MuseDatabase` 同签名的查询层，直接查 `source_songs / source_singers / source_playlists / source_playlist_songs / source_singer_songs`。
- 新增 `assets/igeba_catalog.db`（20.51 MB，`meta.snapshot_utc=2026-10-09T07:33:34Z`，`remote_version=20051590:81801`）；首次启动解压到 `/sdcard/MaidongKTV/database/igeba_catalog.db`，只读打开并校验 `meta.provider=igeba`。
- `SongLibrary.muse` 改为 `IgebaCatalog`；`MainActivity` 启动流程由「下载 muse.db（969 MB）」改为「解压内置目录」，设置页「重置数据库」同步改为重新解压。
- 编号天然对齐：i歌霸歌曲编号即 8 位 `number`，`Song.sourceSongNumber` 直接来自曲库，不再需要歌名匹配索引（原 `IgebaSongIndex` 与其 10 MB 资产已移除）。
- 字段映射要点：`voice_channel → accomp`、`pinyin/pinyin_full → 拼音检索`、`sort_no → 推荐序`、`package_type 3=歌单分类 / 4=榜单`、`region 大陆/港台/欧美/日韩 → 页面「内地/港台/...」`。

### 2.3 下载校验（本次补充）
移植 `SongFileValidator`：
- 非 TS 容器：校验 EBML(MKV) / ftyp(MP4) / ID3/fLaC/RIFF/OggS/同步字，避免把截断文件当成正常文件；
- TS 容器：188 字节包同步 + 首尾 PTS 估时长，短于 60 秒判定预览片；
- 接入 `SongOkDownloadManager.isDownloaded()`（复用文件前）与 `finalizeDownload()`（下载完成后），不合格就清理并重试，不再只看「≥6 MB」。

## 七、本轮已补齐的待办（P0 全量 + P1 两项）

### P0-1　`DownloadSpaceBudget`（磁盘预算）
下载前先用 `StatFs` 算可用空间：单曲按 120 MB + 200 MB 安全余量估，空间不够就直接失败并提示「存储空间不足：剩余 X MB，需要约 Y MB」，不再写半截文件反复重试。设置页的「下载缓存」项会同时显示剩余空间。

### P0-2　`IgebaDownloadRecovery`（断点恢复）
启动后把 `queued / downloading` 的残留任务捡回来重跑：最多 3 首、串行、每首间隔 2 秒，已完整或正在下载的跳过，并把任务状态/D B 同步成「重新下载中」。之前这些任务只会被标成「应用重启，等待重试」然后一直等着。

### P0-3　`OwnedSongCacheCleaner`（自有缓存清理）
只认 `^<7~10位编号>.(mkv|mp4|ts)(.download|.decrypted)?$` 这类「本应用下载并命名」的文件，用户自己拷进目录的（如 `测试歌曲.wav`）一律不碰。入口：设置 → 🎧 音源 → 「下载缓存」，显示「N 个文件，共 X MB（剩余 Y）」，确认后清理，并保留当前播放曲与队列中的编号。

### P0-4　`LegacyStorageUpgrade`（旧目录迁移）
把 `video/cloud-songNNNN/`、`songs/` 里符合命名规则的文件搬到 `video/cloud-song/`，目标已存在且更大就跳过，搬空后删目录。**设备实测**：造一个 `video/cloud-song1/20046950.mkv`，重启后日志 `旧目录迁移：移动 1 个，跳过 0 个，来源 2 个目录`，目录已清空。

### P1（先做一项）　`SongSearchTokens`（搜索归一化）
输入按 空格 / 逗号 / 顿号 / 竖线 拆词（最多 4 个），全角转半角，纯标点词丢弃，SQL 侧改成「词级 AND + 词内 5 字段 OR」。效果：`周 杰 伦`、`刘德华 忘情水`、`ＸＫ`（全角）都能命中，之前整串当 pattern 会一个都搜不到。

### P1-2　`SingerPortraitStore` + `SingerAvatarLoader`（歌手头像库）

歌星页此前只有内置占位图（男/女/组合/未知各 5 张，按名字哈希挑一张），曲库里每行歌手自带的 `image_url` 一直没被用。现在：
