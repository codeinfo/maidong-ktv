# 真机验证流水线（tools/verify.ps1）

> 日期：2026-11-15　|　设备：NX507J（Android 4.4.2 / API 19）　|　目的：把「构建 → 装机 → 唤醒 → 逐页截图 → 日志断言 → 出报告」收成一条命令

## 一、为什么需要它

4.4 真机验证的现状是硬约束：SDK 里没有 emulator（`ktv_api19` AVD 已不可用）、`input tap` 在应用内不生效、只能靠 `keyevent` + `KeyTrace` 日志 + 截图肉眼比对。历史上每轮验证要手工串 5～6 条 adb 命令，还出现过「设备在锁屏、按键全被 Keyguard 吞掉，白跑一轮」的情况。

`tools/verify.ps1` 把这些固定动作脚本化，单轮从十几分钟压到**一条命令 + 一份报告**（含构建约 3 分钟）。

## 二、怎么用

```powershell
# 默认：debug 包，跑 home/singers/local/settings/tuning 五页，含构建
pwsh -File tools\verify.ps1

# 复用现有 APK，只跑设备侧
pwsh -File tools\verify.ps1 -SkipBuild

# 指定页面（qa_open 支持：singers | local | guess | tuning | fullscreen | status | settings | settingsdata | portraitclear）
pwsh -File tools\verify.ps1 -Pages "home,settings,tuning" -SkipBuild

# 验证正式包（无可用的 qa_open，只跑首页与崩溃检查）
pwsh -File tools\verify.ps1 -Variant release
```

参数：`-Serial`（默认 `NX507J`）、`-Variant`（`debug` 跑 `com.local.ktv.qa`，`release` 跑 `com.local.ktv`）、`-SettleSeconds`（每页等待，默认 8，冷启动解压曲库时建议 10）、`-OutDir`。

> 注意：`pwsh -File` 不做数组解析，`-Pages` 必须传**逗号分隔的一个字符串**，脚本内部再拆分。

退出码：`0` 全部通过 / `1` 有失败项 / `2` 环境缺失（adb、JDK、设备不在线）。

## 三、脚本做了什么

| 步骤 | 动作 | 失败即中断 |
| --- | --- | --- |
| 1 | 检查 adb、JDK 17、设备是否 `device` 状态 | 是 |
| 2 | `gradlew assemble<Variant>`（`--no-daemon`、in-process Kotlin） | 是 |
| 3 | `adb install -r` | 是 |
| 4 | 锁屏护栏：`dumpsys window` 命中 `Keyguard` 时自动 `keyevent 224/82 + swipe`，仍锁屏则退出并提示手动解锁 | 是 |
| 5 | 逐页：`force-stop` → `am start [--es qa_open <page>]` → 等待 → `screencap` 拉回本地 | 否（记为失败项） |
| 6 | 断言：截图有效性、`FATAL EXCEPTION`、`qa_open` 是否命中、页面间截图是否重复 | 否（记为失败项） |
| 7 | 生成 `verify-report.md`（环境、页面表、每页 KeyTrace、失败项） | — |

## 四、判定规则（避免“看着像通过”）

1. **截图有效性**：解析 PNG 头拿宽高，要求 ≥ 640×480 且 > 5 KB。不能按文件体积判断——全屏播放器黑屏压缩后只有 30 KB 左右，按体积会被误判为“截图缺失”。
2. **崩溃**：每页 `logcat -c` 后跑一次，抓 `FATAL EXCEPTION`。
3. **qa_open 命中**：按**设备时间戳**裁剪 `app.log` 里本页启动之后的 `KeyTrace` 行，避免把上一页的日志算到本页。
4. **页面真的切了没有**：截图 MD5 与首页、以及与前面任意一页比对，完全相同即判定“页面未真正切换”。这一条是本脚本发现真 bug 的关键（见下）。

## 六、顺带修掉的 bug：`qa_open` 被首屏覆盖

| 项 | 内容 |
| --- | --- |
| 现象 | 日志明明打印 `qa_open 已打开 singers/local/settings`，截图却仍停在首页；`tuning`、`fullscreen` 正常 |
| 根因 | 首访要解压 20.5 MB 曲库，`maybeOpenQaPage()` 的 1.5s / 7s 两次跳转都发生在曲库就绪回调之前，随后 `refreshLibrary` 里的 `showHomePage()` 把页面覆盖回首页 |
| 修复 | 在曲库就绪回调（`refreshLibrary` 内 `showHomePage()` 之后）再调用一次 `maybeOpenQaPage()`，正式包因 `BuildConfig.DEBUG == false` 不受影响 |
| 验证 | 修复前 singers/local/settings 三张截图 MD5 完全相同；修复后六张全不相同，settings 页可见「数据设置/播放设置/声音设置/关于」四张卡片 |

## 七、已知限制

1. **像素级查重只能发现“完全相同”**：首页轮播、播放画面每帧都在变，首页截图天然与其它页不同，所以“某页其实停在首页但轮播刚好转了一格”仍会漏判。要彻底解决需要区域裁剪或忽略底部轮播区，暂未做。
2. **正式包无 `qa_open`**：`maybeOpenQaPage()` 有 `BuildConfig.DEBUG` 守卫，`-Variant release` 只能验证首页渲染与崩溃。
3. **设备有密码锁**：脚本只能做「唤醒 + MENU 键 + 上滑」，设置了口令锁的机器会直接失败退出，需人工解锁后重跑。
4. **单设备串行**：一次只跑一台，未做多设备并行（现场也只有一台 4.4 真机）。
5. **不覆盖播放链路**：切唱、字幕、遥控器 ←/→ 这类交互断言还需要按键序列支持（下一步可加 `-Keys` 参数，复用 `KeyTrace` 做焦点断言）。
