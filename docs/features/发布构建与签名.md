## 五、升级影响（重要）

1. **旧正式版设备**：用原签名装过 1.1.0 的机器，新包会报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`（签名不一致），只能卸载后重装 —— 卸载会清掉已下载歌曲与曲库状态。
2. **调试包不受影响**：`com.local.ktv.qa` 用的是 Android 默认 debug.keystore，与本次发布签名无关，可继续共存。
3. **若日后找回原签名**：把原 `ktv_keystore.jks` 放到 `E:\ktv\` 并改 `keystore.properties` 的密码即可恢复「可覆盖升级」，无需改代码。
4. **务必备份**：`ktv_keystore.jks` 与 `keystore.properties` 一旦丢失，后续所有版本都无法覆盖升级，只能再次换签名重装。建议线下备份（U 盘/加密存储）。

## 六、更换/重建签名

```powershell
$kt = Join-Path $env:JAVA_HOME "bin\keytool.exe"
& $kt -genkeypair -v -keystore E:\ktv\ktv_keystore.jks -alias ktv -keyalg RSA -keysize 2048 `
  -validity 10950 -storepass "<你的密码>" -keypass "<你的密码>" `
  -dname "CN=Maidong KTV, OU=Android, O=Maidong, L=Luoyang, ST=Henan, C=CN" -storetype JKS
```

然后同步修改 `keystore.properties` 的 `storePassword`/`keyPassword`。

## 七、注意

- **不要把 `ktv_keystore.jks` 或 `keystore.properties` 提交进 git**，也不要把密码写进任何入库文档。
- `versionCode` 目前仍是 2（1.1.0）。若对外发布多个迭代包，记得逐次递增，否则同签名下也无法降级安装。
