## 8. 播放能力补齐：平台 MediaPlayer 兜底 + 模拟器实测

### 8.1 原限制与判断

播放引擎 `KtvPlaybackEngine` 只走 IJK；`jniLibs` 只有 `armeabi-v7a`，x86 系统镜像加载不了 ARM 原生库，原代码在 IJK 缺失时直接 `errorListener.onError(...)` 并显式注明「platform fallback is disabled」。因此本模拟器永远播不了，与曲库是否有本地媒体无关。

结论：这不是「环境不具备」，而是**引擎做了单路径硬依赖**。补齐一条平台解码路径即可在 x86 模拟器（以及任何缺 ARM 原生库的设备）上完成播放验证，同时不影响 ARM 真机继续用 IJK。

### 8.2 改动（`app/src/main/java/com/local/ktv/player/KtvVideoView.kt`）

| 项 | 改法 |
| --- | --- |
| 引擎选择 | `setVideoUri` 中若 IJK 不可用（或重建两次仍失败），改调 `playWithPlatform(uri)`；ARM 上 IJK 正常时行为完全不变 |
| 平台播放器 | 新增 `platformPlayer: MediaPlayer`，`ensurePlatformPlayer` / `configurePlatform` / `preparePlatformPlayer` / `releasePlatform` 四个私有方法 |
| 状态读取 | `isPlaying` / `currentPosition` / `duration` 同时兼容 IJK 与平台播放器（注意 IJK 是 `Long`、平台是 `Int`，已统一转 `Long` 再截断） |
| 控制面 | `start` / `pause` / `seekTo` / `stop` / `setVolume` 双路径；`release` / `setOutputHolder` / `surfaceDestroyed` 同时下发到两个播放器 |
| 原唱/伴唱切换 | 平台路径下 `selectAudioTrack` 返回 `false`（系统 MediaPlayer 无法切音轨）；`selectAudioChannel` 复用 `setVolume` 实现左右声道 |
| 失败缓存 | 首次 `UnsatisfiedLinkError` 后置 `ijkNativeUnavailable = true`，后续播放直接走平台路径，避免每次播放都抛一次异常栈、也不再产生 `native_finalize` 的 `UnsatisfiedLinkError` 噪声 |

### 8.5 附带发现：模拟器「自己退出」的真因

本轮前后三次模拟器消失，日志均为**优雅退出**（`Wait for emulator … shutdown gracefully`、`Saving snapshot 'default_boot'`），不是崩溃，Windows 事件日志也没有 `Application Error` 记录。

真因：emulator 通过 PowerShell 的 `Start-Process` 启动时继承了该命令的 stdin；命令/后台任务结束后 stdin 关闭，emulator 控制台读到 EOF 便按正常流程退出（延迟不定，因此看起来像「跑几分钟就挂」）。

规避：用 `cmd /c start "" emulator.exe …` 完全分离启动，本轮视频播放实测期间模拟器全程存活。

### 8.6 仍未覆盖

- 真机 ARM 路径（IJK）本轮没有设备可测，改动对 IJK 分支是「无 IJK 才走平台」，逻辑上不影响，但仍建议 ARM 4.4.4 盒子回归一次。
- 原唱/伴唱切换、字幕、TS 老片源等依赖 IJK 特性项，在平台兜底路径下不生效（`selectAudioTrack` 返回 false）。
- 视频素材是补零伪装的 mp4（仅为过 6MB 门槛），不能作为正式视频兼容性结论。
